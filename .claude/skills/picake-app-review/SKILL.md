# 앱 화면 검토·다듬기 (판매자 앱·손님 앱)

운영자는 화면을 글보다 그림으로 판단하고, 고르는 것을 직접 한다. 2026-11-10에 판매자 앱을 이 방식으로 17번 검토했고(I-48 진행 기록), 11-11에 손님 앱(#307~#309)·움직임(#311)·앱 느낌(#312)을 같은 방식으로 했다. 아래는 그때 굳은 방식이다. "N분 동안", "최소 1시간"처럼 시간을 정하면 시작 시각을 scratchpad에 적어 두고 그 시간이 다 될 때까지 각도를 바꿔 본다. 몇 분 지났는지는 **반드시 `date`로 잰 값만** 말한다(13차에 짐작으로 말해 틀렸음).

## 1. 로컬에서 직접 눌러 보기

작업 공간 `CLAUDE.md`의 "로컬에서 화면까지 직접 테스트하는 법"을 따른다(운영·staging 계정으로는 로그인하지 않는다). 덧붙여:

- **손님 앱**: `apps/web-user`에서 `NEXT_PUBLIC_API_DOMAIN=http://localhost:3000 npx next dev -p 3001`(빌드 결과 `.next`가 있으면 먼저 지운다. 개발 서버를 켠 채 `next build`를 돌리면 `.next`를 덮어써 500이 난다). 로그인은 `localStorage["picake:auth"] = {state:{isAuthenticated:true, accessToken}, version:0}`에 테스트 DB 손님 토큰. 화면은 `#root-scroll-container` 안에서 스크롤한다. 개발 표시(`nextjs-portal`, TanStack 야자수 버튼 `.tsqd-parent-container`)가 누르기를 가리면 CSS로 숨긴다. Playwright `locator.click()`은 누르기 전에 스크롤을 옮기므로 스크롤 자리를 볼 때는 화면에 보이는 점을 `page.mouse.click`으로 누르고 `mouse.wheel`로 내린다. `packages/design-tokens`(색·겹침 순서·움직임 이름)를 바꾸면 켜 둔 개발 서버(손님·판매자 둘 다)는 새 이름을 만들지 못하니 다시 켠다(`z-modal`이 `auto`로 보임).

- **토큰을 브라우저에 넣기**: Playwright 코드에서는 파일을 못 읽으므로, 토큰을 넣은 JS 파일을 `.playwright-mcp/`에 만들어 `browser_run_code_unsafe`의 `filename`으로 돌린다. 로그인 화면이 다 뜬 뒤 `localStorage.accessToken`에 넣는다(먼저 넣으면 첫 화면의 401이 지운다).
- **앱 안처럼**: init script로 `window.flutter_inappwebview.callHandler`를 흉내 내고 알림 권한 요청에 `receivePushPermission('granted')`로 답한다. 화면은 390×844.
- **상태별 주문**: 백엔드 `src/test/e2e/tmp-*.script.ts` 임시 시드(처음에 `assertTestDatabase()`, 끝나면 지움)로 상태 10가지 예시 주문을 넣는다. nest가 컴파일하는 중에는 만들지 않는다.
- **서버 응답 흉내**: 실제로 못 만드는 화면(네이버 연결·사업자 조회·가입)은 `page.route`로 응답을 바꿔 연다.
- **화면 전체 점검**: 화면 20여 개를 돌며 이 폴더의 [`audit.js`](audit.js)를 `browser_run_code_unsafe`의 `filename`으로 돌린다. 지금 화면의 기준 밖 글자 크기·색(앱마다 다름), 40 아래 누르는 칸, 이름 없는 버튼(화면 읽기), 360 폭 넘침, 공용 값이 아닌 움직임 시간을 뽑는다. 고친 뒤 다시 돌려 없어졌는지 본다. 기준 값이 바뀌면 `audit.js`도 맞춘다.
- **느린 인터넷**: `page.context().newCDPSession(page)` → `Network.emulateNetworkConditions`(지연 800ms)로 누르자마자 바뀌는지(하트·스위치·탭), 화면 이동 중 뼈대가 보이는지 본다. 끝나면 되돌린다.
- **불러오는 중·실패**: `page.route`로 서버 응답을 3초 늦추거나 500으로 바꿔 화면마다 기다리는 모양·실패 모양이 같은지 본다(한 장에 모아 찍기).
- **흐름 따라가기**: 저장 → 어디로 가는지 → 뒤로를 누르면 어디인지(`page.goBack()`), 처음 가입 → 스토어 만들기 → 첫 화면, 로그인이 풀린 채 알림 열기. 저장은 `page.route`로 성공 응답을 흉내 내 테스트 DB를 바꾸지 않는다.
- **화면 밖 규칙**: 지우기·바꾸기가 서버·DB에서 무엇까지 지우는지(`schema.prisma`의 `onDelete`), 손님에게 실제로 보이는 글인지(손님 앱·알림톡 코드)를 확인한다. 13차에 상품을 지우면 주문까지 지워지는 것을 찾았다.
- **끝부분 경우**: 끊김 `page.context().setOffline(true)`, 키보드 `setViewportSize`로 높이만 줄이기, 배포 직후 화면 조각 실패 `vite build --outDir <scratchpad>` + `vite preview --port 3001` + 조각 하나 지우기, 작년 날짜·긴 이름·큰 숫자는 시드나 `page.route`로.

## 2. 볼 곳 (검토 각도)

한 번 볼 때 각도를 바꿔 가며 본다. "더 있을 것 같아"라고 하면 지난번에 안 본 각도부터.

1. **같은 일 = 같은 모양**: 저장·삭제 버튼 자리와 이름, 고르기 칸, 켜고 끄기, 칸 옆 버튼, 빈 화면, 창 버튼 줄. 고칠 때는 비슷한 화면을 먼저 찾아 그 모양에 맞추고, 같은 문제가 있는 다른 화면도 같이 고친다.
2. **휴대폰 틀 안 PC 화면**(상품 등록·수정, 스토어 정보·만들기, 피드): PC 부품·PC 말("노출", "영업 캘린더")이 남은 곳.
3. **상태별**: 주문 상태 10가지, 처리 창, 끝난 주문, 쉬는 날.
4. **끝부분**: 끊김, 새 버전 직후, 키보드, 긴 이름, 큰 숫자, 작년 날짜, 처리 중 두 번 누르기.
5. **글**: 해요체(고칠 곳 문구·검사 함수까지), "손님", 한 일을 말하는 안내, 띄어쓰기, 예시 글, 같은 값은 같은 이름(카드와 상세), 손님에게 보이는 글인지(손님 앱·알림톡을 찾아 확인).
6. **불러오는 중·실패·빈 칸 저장**: 늦은 응답, 500, 빈 칸으로 저장 눌렀을 때 고칠 곳 문구.
7. **한 화면씩 끝까지**: 전체 화면(fullPage)으로 찍어 위에서 아래까지 본다.
8. **흐름·기기**: 저장 뒤 뒤로, 처음 쓰는 사장님(빈 스토어·스토어 만들기 2단계), 아주 작은 휴대폰(320), 앱 안(브리지 흉내), 키보드 이동 키, 복사·스위치처럼 바로 되는 일의 안내.
9. **실제 가게처럼 많을 때·몰릴 때**: 손님 주문 API(`POST /v1/consumer/orders`, 테스트 DB 손님 토큰)로 예약 20개를 몇 초에 넣어 실시간 알림·목록이 버티는지, `page.on('request'/'response')`로 사장님 앱 요청 수와 429를 센다. 주문 60개 목록 끝까지, 사진 8장, 스토어 여러 개(`page.route`), 긴 요청사항·이름. 손님 요청은 `X-Forwarded-For`를 달리 줘 사장님 요청 한도와 섞이지 않게 한다(15차에 서버 요청 한도가 모두 한 칸이던 것을 찾음).
10. **실제 쓰는 순간**: 픽업하러 온 손님 찾기(이름·번호 뒷자리), 앱을 켜 둔 채 새 예약이 올 때 안내를 눌러 보기, 대표 사진 바꾸기처럼 사장님이 하루에 여러 번 하는 일을 처음부터 끝까지.
11. **시간·동시에**: `page.clock.install`로 밤 11시 58분에 열고 `runFor`로 자정을 넘겨 "오늘"이 바뀌는지, 소켓을 막은 채(`routeWebSocket`) 다른 기기에서 먼저 바꾼 주문을 처리할 때 안내·화면(16차).
12. **앱 느낌**(11-11 밤 검토): 누를 때 반응(`press`), 글자 길게 눌러 선택, 보고 있는 탭 다시 누르기, 뒤로 가면 스크롤 자리, 누르자마자 바뀌는지(서버를 기다리지 않음), 화면 이동 중 흰 화면, 사진 오기 전 빈칸, 어두운 모드에서 색이 뒤집히는지, iOS 입력 칸 확대, 단계 넘김.
13. **화면 읽기(접근성)**: 이름 없는 아이콘 버튼, 탭·고르기 칸의 역할(`role=tab`·`aria-selected`), 지금 탭(`aria-current` 하나), 창(`role=dialog`·`aria-modal`), 안내 띠(`aria-live`).

## 3. 보여 주고 고르게 하기

1. 고칠 것을 로컬에서 먼저 고친다. 바꾸기 전 화면은 `git stash push -- <파일>`로 잠깐 치워 두고 찍는다.
2. 후보마다 그림 한 장: 왼쪽 "지금" · 오른쪽 "바꾸면" + 두세 줄 설명(무엇이 이상하고, 어떻게 바꾸는지). 모양을 여러 안 중에 고르는 것(효과·자리)은 안마다 그림.
   - 비교 페이지(`.playwright-mcp/cmp.html`)를 `python3 -m http.server 8765`로 열고 카드마다 찍는다. 다시 찍을 때는 `?v=N`.
   - 그림은 scratchpad로 옮겨 `SendUserFile`로 보낸다.
3. `AskUserQuestion`(multiSelect, 질문 하나에 선택지 4개까지)으로 고르게 한다. 추천은 맨 앞에 "(추천)".
4. **고른 것만 남기고 안 고른 것은 되돌린다.** 안 고른 것은 아래 "다시 꺼내지 않을 것"에 더한다.

## 4. 고른 뒤

- 검사: `prettier`, `tsc --noEmit`, `eslint`(`yarn common:lint`), 앱별 단위 테스트, `yarn web-seller:build`·`yarn web-user:build`(개발 서버를 멈추고)·공용 값을 바꿨으면 `yarn web-info:build`.
- **손님 앱 글·class를 바꿨으면 e2e**: `cd apps/web-user && yarn test:e2e`(3000·3001이 떠 있으면 그대로 쓰고, 없으면 마이그레이션·시드·서버를 띄운다). 11-11에 글("오류"→"확인", "모두 동의해요")과 class(`.animate-slide-up`)를 바꿔 e2e 3개가 깨졌다. 찾는 말은 글 대신 역할(`getByRole("dialog")`)로 쓰는 쪽이 오래 간다. PR을 올린 뒤 `test-web-e2e` 결과도 본다(필수 체크는 아님).
- 커밋(`[WEB-SELLER]`·`[WEB-USER]`·공용은 `[COMMON]`) → draft PR(base `staging`, assignee `geunu97`)은 묻지 않고 한다. 앞 PR 위에 쌓으면 본문에 합치는 순서를 적는다. **staging·상용은 운영자가 말할 때만**("스테이징에 올려줘", "상용까지").
- 같이 고칠 곳: 그 앱 디자인 기준 문서, 기획 `picake-product` 아이디어 진행 기록(판매자 앱 I-48)과 `CHANGELOG.md` `## 다음 버전`("검토 중, 서비스에는 아직 없음"), hq `today/todo.md`(앱에서 운영자가 볼 것).
- 상용에 나가면 작업 공간 `CLAUDE.md`의 "기능을 만들면 같이 고칠 곳" 표대로(기획서 F-62, 버전 확정 등).
- 끝나면 서버를 멈추고 `.playwright-mcp/`와 토큰 파일을 지운다.
