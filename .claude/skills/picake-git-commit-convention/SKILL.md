# 커밋 메시지 규칙

이 레포(`picake-engineering-web`)는 웹 전용입니다. backend 레포는 `[BE]`/`[COMMON]`을 씁니다.

## 형식

```
[접두사]: 내용
```

- 접두사는 아래 4개 중 변경 범위에 맞는 것 하나를 사용합니다.
  - `[WEB-USER]`
  - `[WEB-SELLER]`
  - `[WEB-ADMIN]`
  - `[WEB-INFO]`
  - `[COMMON]`
- 내용(본문)은 한국어로 작성합니다.

## 접두사 선택 기준

| 접두사         | 대상                                                                |
| -------------- | ------------------------------------------------------------------- |
| `[WEB-USER]`   | `apps/web-user` 변경                                                |
| `[WEB-SELLER]` | `apps/web-seller` 변경                                              |
| `[WEB-ADMIN]`  | `apps/web-admin` 변경                                               |
| `[WEB-INFO]`   | `apps/web-info` 변경                                                |
| `[COMMON]`     | 특정 앱에 한정되지 않는 공통 변경 (루트 설정, 여러 앱 동시 변경 등) |

`git status`로 변경된 파일이 어느 앱/영역에 속하는지 먼저 확인한 뒤 접두사를 정합니다.

## 예시

```
[WEB-USER]: 로그인 페이지 접근성 개선
[WEB-SELLER]: 상품 등록 폼 검증 오류 수정
[COMMON]: ESLint 설정 업데이트
```

## 주의

- 사용자가 명시적으로 요청하지 않으면 커밋하지 않습니다.

## 커밋 절차

사용자가 커밋을 요청했거나 `/commit`을 실행했을 때의 절차입니다.

### 1. 변경사항 파악

```bash
git status --short
git diff --stat
git diff            # 수정된 파일
git diff --staged   # 이미 스테이징된 것이 있으면
```

새 파일(`??`)의 내용도 반드시 읽습니다. diff에 안 나옵니다.

### 2. 타입체크

```bash
yarn workspace @picake/<앱> exec tsc --noEmit   # 변경된 앱마다
```

실패하면 **커밋하지 말고** 사용자에게 알립니다. 린트(`yarn common:lint`)는 `--max-warnings=0`이라 기존 경고만으로도 실패합니다. 돌린다면 기존 경고 수와 비교해서 늘었을 때만 문제 삼습니다.

### 3. 논리 단위로 분리

성격이 다른 변경은 **커밋을 나눕니다.** 파일이 겹치지 않으면 나누는 쪽이 기본입니다. 기능 추가와 버그 수정, 서로 다른 화면/도메인, 리팩터링과 동작 변경은 분리하고, 한 기능을 위해 함께 움직여야 하는 파일은 같은 커밋에 둡니다. 사용자가 "한 커밋으로"라고 하면 합칩니다.

### 4. 메시지 작성

```
[접두사]: 무엇을 했는지 (한국어, 50자 내외)

왜 이 변경이 필요했는지 — 문제 상황부터.

- 핵심 변경점
- 판단이 갈릴 수 있었던 지점과 그 이유
- 측정값이 있으면 숫자로 (예: /products 4건 → 2건)
```

본문은 "무엇을 바꿨는지"가 아니라 "왜 그렇게 했는지"를 씁니다. 무엇을 바꿨는지는 diff에 이미 있습니다. 끝에 `Co-Authored-By: <현재 세션의 실제 모델명> <noreply@anthropic.com>`을 붙입니다(세션마다 다르므로 고정값을 쓰지 않습니다).

### 5. 커밋

경로에 `[productId]` 같은 대괄호가 있으면 따옴표로 감쌉니다.

```bash
git add "<파일들>"
git commit -F - <<'MSG'
...
MSG
```

`.git/index.lock` 오류가 나면 **바로 지우지 말고** 먼저 확인합니다.

```bash
pgrep -lf "bin/git " || echo "실행 중인 git 없음"
ls -la .git/index.lock
```

git 프로세스가 없고 lock이 오래된 0바이트 파일이면 stale이므로 제거하고 진행합니다. 실행 중인 git이 있으면 사용자에게 알리고 멈춥니다.

### 6. 보고

커밋 해시와 제목을 나열하고, **푸시는 하지 않았다**고 명시합니다. 푸시·배포가 필요하면 `/push-staging`을 안내합니다.
