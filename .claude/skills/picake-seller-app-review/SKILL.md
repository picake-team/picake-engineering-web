# 판매자 앱 검토·다듬기

운영자는 화면을 글보다 그림으로 판단하고, 고르는 것을 직접 한다. 2026-11-10에 이 방식으로 13번 검토했고(I-48 진행 기록), 아래는 그때 굳은 방식이다. "N분 동안", "최소 1시간"처럼 시간을 정하면 시작 시각을 scratchpad에 적어 두고 그 시간이 다 될 때까지 각도를 바꿔 본다. 몇 분 지났는지는 **반드시 `date`로 잰 값만** 말한다(13차에 짐작으로 말해 틀렸음).

## 0. 먼저 읽기

- 디자인 규칙: [`docs/web-seller/판매자 앱 디자인 기준.md`](../../../docs/web-seller/판매자%20앱%20디자인%20기준.md). 고칠 때 이 문서의 부품·크기·글 규칙을 따르고, 새 규칙이 생기면 이 문서에 더한다.
- 부품: `apps/web-seller/src/common/ui`(Storybook "판매자 앱/부품"). 화면 안에서 비슷한 것을 새로 만들지 않는다.
- 아래 "다시 꺼내지 않을 것"을 확인한다.

## 1. 로컬에서 직접 눌러 보기

작업 공간 `CLAUDE.md`의 "로컬에서 화면까지 직접 테스트하는 법"을 따른다(운영·staging 계정으로는 로그인하지 않는다). 덧붙여:

- **토큰을 브라우저에 넣기**: Playwright 코드에서는 파일을 못 읽으므로, 토큰을 넣은 JS 파일을 `.playwright-mcp/`에 만들어 `browser_run_code_unsafe`의 `filename`으로 돌린다. 로그인 화면이 다 뜬 뒤 `localStorage.accessToken`에 넣는다(먼저 넣으면 첫 화면의 401이 지운다).
- **앱 안처럼**: init script로 `window.flutter_inappwebview.callHandler`를 흉내 내고 알림 권한 요청에 `receivePushPermission('granted')`로 답한다. 화면은 390×844.
- **상태별 주문**: 백엔드 `src/test/e2e/tmp-*.script.ts` 임시 시드(처음에 `assertTestDatabase()`, 끝나면 지움)로 상태 10가지 예시 주문을 넣는다. nest가 컴파일하는 중에는 만들지 않는다.
- **서버 응답 흉내**: 실제로 못 만드는 화면(네이버 연결·사업자 조회·가입)은 `page.route`로 응답을 바꿔 연다.
- **화면 전체 점검**: 화면 20여 개를 돌며 크기 기준 밖 글자(11·12·13·15·16·18·20 밖), 색 기준 밖, 40 아래 누르는 칸, 48/40/36 밖 높이, 360 폭 넘침을 한 번에 뽑는 스크립트를 돌린다(`page.evaluate`로 `getComputedStyle`). 고친 뒤 다시 돌려 없어졌는지 본다.
- **불러오는 중·실패**: `page.route`로 서버 응답을 3초 늦추거나 500으로 바꿔 화면마다 기다리는 모양·실패 모양이 같은지 본다(한 장에 모아 찍기).
- **흐름 따라가기**: 저장 → 어디로 가는지 → 뒤로를 누르면 어디인지(`page.goBack()`), 처음 가입 → 스토어 만들기 → 첫 화면, 로그인이 풀린 채 알림 열기. 저장은 `page.route`로 성공 응답을 흉내 내 테스트 DB를 바꾸지 않는다.
- **화면 밖 규칙**: 지우기·바꾸기가 서버·DB에서 무엇까지 지우는지(`schema.prisma`의 `onDelete`), 손님에게 실제로 보이는 글인지(손님 앱·알림톡 코드)를 확인한다. 13차에 상품을 지우면 주문까지 지워지는 것을 찾았다.
- **끝부분 경우**: 끊김 `page.context().setOffline(true)`, 키보드 `setViewportSize`로 높이만 줄이기, 배포 직후 화면 조각 실패 `vite build --outDir <scratchpad>` + `vite preview --port 3001` + 조각 하나 지우기, 작년 날짜·긴 이름·큰 숫자는 시드나 `page.route`로.

## 2. 볼 곳 (검토 각도)

한 번 볼 때 각도를 바꿔 가며 본다. "더 있을 것 같아"라고 하면 지난번에 안 본 각도부터.

1. **같은 일 = 같은 모양**: 저장·삭제 버튼 자리와 이름, 고르기 칸, 켜고 끄기, 칸 옆 버튼, 빈 화면, 창 버튼 줄. 고칠 때는 비슷한 화면을 먼저 찾아 그 모양에 맞추고, 같은 문제가 있는 다른 화면도 같이 고친다.
2. **휴대폰 틀 안 PC 화면**(상품 등록·수정, 스토어 정보·만들기, 피드): PC 부품·PC 말("노출", "영업 캘린더")이 남은 곳.
3. **상태별**: 주문 상태 10가지, 처리 창, 끝난 주문, 쉬는 날.
4. **끝부분**: 끊김, 새 버전 직후, 키보드, 긴 이름, 큰 숫자, 작년 날짜, 처리 중 두 번 누르기.
5. **글**: 해요체(고칠 곳 문구·검사 함수까지), "손님", 한 일을 말하는 안내, 띄어쓰기, 예시 글, 같은 값은 같은 이름(카드와 상세), 손님에게 보이는 글인지(손님 앱·알림톡을 찾아 확인).
6. **불러오는 중·실패·빈 칸 저장**: 늦은 응답, 500, 빈 칸으로 저장 눌렀을 때 고칠 곳 문구.
7. **한 화면씩 끝까지**: 전체 화면(fullPage)으로 찍어 위에서 아래까지 본다.
8. **흐름·기기**: 저장 뒤 뒤로, 처음 쓰는 사장님(빈 스토어·스토어 만들기 2단계), 아주 작은 휴대폰(320), 앱 안(브리지 흉내), 키보드 이동 키, 복사·스위치처럼 바로 되는 일의 안내.

## 3. 보여 주고 고르게 하기

1. 고칠 것을 로컬에서 먼저 고친다. 바꾸기 전 화면은 `git stash push -- <파일>`로 잠깐 치워 두고 찍는다.
2. 후보마다 그림 한 장: 왼쪽 "지금" · 오른쪽 "바꾸면" + 두세 줄 설명(무엇이 이상하고, 어떻게 바꾸는지). 모양을 여러 안 중에 고르는 것(효과·자리)은 안마다 그림.
   - 비교 페이지(`.playwright-mcp/cmp.html`)를 `python3 -m http.server 8765`로 열고 카드마다 찍는다. 다시 찍을 때는 `?v=N`.
   - 그림은 scratchpad로 옮겨 `SendUserFile`로 보낸다.
3. `AskUserQuestion`(multiSelect, 질문 하나에 선택지 4개까지)으로 고르게 한다. 추천은 맨 앞에 "(추천)".
4. **고른 것만 남기고 안 고른 것은 되돌린다.** 안 고른 것은 아래 "다시 꺼내지 않을 것"에 더한다.

## 4. 고른 뒤

- 검사: `prettier`, `tsc --noEmit`, `eslint`, `yarn workspace @picake/web-seller test`, `yarn web-seller:build`.
- 커밋(`[WEB-SELLER]`) → draft PR(base `staging`, assignee `geunu97`)은 묻지 않고 한다. **staging·상용은 운영자가 말할 때만**("스테이징에 올려줘", "상용까지").
- 같이 고칠 곳: 디자인 기준 문서, 기획 `picake-product` I-48 진행 기록과 `CHANGELOG.md` `## 다음 버전`("검토 중, 서비스에는 아직 없음"), hq `today/todo.md`(앱에서 운영자가 볼 것).
- 상용에 나가면 작업 공간 `CLAUDE.md`의 "기능을 만들면 같이 고칠 곳" 표대로(기획서 F-62, 버전 확정 등).
- 끝나면 서버를 멈추고 `.playwright-mcp/`와 토큰 파일을 지운다.

## 다시 꺼내지 않을 것 (운영자가 고르지 않음)

- 스토어 정보 환불 규정 "+ 추가" 버튼 모양 바꾸기(11-10 5차)
- 상품 상세 설명 편집 도구 줄 줄이기(굵게·목록·사진만, 11-10 8차)
- 스토어 정보 "ID는 어디서 찾나요?" 펼치기 모양(▶ → ⌄, 11-10 8차)
- 캘린더에서 쉬는 날로 바꾼 날의 이미 받은 픽업 점 표시(11-10 9차)
- 상품 목록·공유 창 상품 이름, 스토어 탭 스토어 이름을 두 줄까지(11-10 13차)
- 예약 확인 창의 "확인하면 손님이 입금할 수 있어요…" 한 줄, 모든 요일을 쉬면 나오는 주의 안내(11-10 13차)
- 로그인이 풀려 로그인 화면으로 오면 "로그인이 풀렸어요…" 한 줄(11-10 13차)
- 같은 안내(복사 등)를 여러 번 띄우면 하나만 남기기(11-10 13차)
- 틀 안 화면에서 키보드 "이동(Enter)"을 다음 칸으로(지금은 폼 제출, 11-10 13차)
- 앱을 내렸다 다시 열면 주문·알림 새로 불러오기·끊긴 연결 다시 붙이기, 캘린더 당겨서 새로 고침(11-10 13차)
- 앱 안에서는 태블릿·아이패드 폭에서도 휴대폰 화면(지금은 768 이상이면 PC 화면, 11-10 13차)

운영자가 나중에 직접 꺼내면 그때 다시 본다.

## 정한 방향

- 판매자 화면은 단순하게: 한 화면에 한 가지, 행동 이름 버튼, 고급 기능은 접기.
- 흐름은 토스처럼 쉽고 빨리 끝나게(한 화면에 묻는 것 하나, "다음"만 누르면 이어짐): 기획 아이디어 I-58. 새 흐름을 만들거나 크게 고칠 때 먼저 본다.
