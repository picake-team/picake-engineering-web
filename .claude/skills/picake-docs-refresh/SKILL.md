# 문서 최신화

특정 변경에 딸려오는 게 아니라, "지금 시점 기준으로 문서를 정확하게 맞춰달라"는 요청을 처리하는 절차입니다.

## 1. 범위 확인

사용자가 특정 문서/영역(예: "web-seller 문서만", "README만")을 지정했으면 그 범위만 봅니다. 지정하지 않았다면 루트 `README.md`와 `docs/` 폴더 전체가 대상입니다.

## 2. 문서를 하나씩 코드와 대조

각 문서를 읽고 실제 코드베이스 상태와 비교합니다. 특히 아래처럼 코드가 바뀌면 쉽게 틀어지는 부분을 중점적으로 확인하세요.

- `package.json`의 스크립트 명령어, 포트 번호, Node/Yarn 버전 등 (루트 `README.md`의 "시작하기" 섹션)
- 실제 디렉토리 구조 vs `docs/common/structure/프로젝트 구조 - 가이드.md`의 트리
- 기술 스택/주요 라이브러리 vs 각 앱의 `기술 스택 - 가이드.md`
- API 경로, 인증 방식 등 vs `docs/common/feature/`의 기능 가이드
- 배포 태그 형식, 워크플로우 파일 경로 vs `docs/infra/`, 루트 README의 배포 섹션
- README의 "📚 상세 문서" 목차와 `docs/` 폴더 안에 실제로 존재하는 파일 목록이 서로 맞는지 (없어진 문서로의 링크, 새로 생겼는데 목차에 없는 문서 등)

파일명에 `(구버전)`/`(이전버전)`처럼 특정 시점의 버전이 명시된 문서는 그 시점 상태를 의도적으로 보존하는 기록이므로 "최신화" 대상에서 제외합니다. 깨진 링크처럼 명백한 오류가 아니라면 손대지 않습니다.

## 3. 발견한 내용 바로 수정

문서가 여러 개 걸려도 사용자에게 하나하나 확인받지 않고 바로 수정합니다.

## 4. 작성 원칙

- **민감 정보 금지**: API 키, 토큰, 비밀번호, 시크릿, 내부 IP/호스트, 실제 사용자 데이터 등은 어떤 경우에도 문서에 남기지 않습니다.
- **핵심 요약만**: 중요하지 않다고 판단되는 세부 내용은 굳이 채워 넣지 않아도 됩니다. 주요 내용과 그 요약 위주로 정리합니다.
- 기존 문서의 언어(한국어)와 톤, 파일명 규칙(`... - 가이드.md`), 표/코드블록 스타일을 그대로 따릅니다.

## 5. 마무리 보고

수정한 문서 목록과 각각 무엇을 왜 고쳤는지 짧게 요약해서 알려줍니다.
