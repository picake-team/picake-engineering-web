# 판매자 앱 디자인 기준

판매자 휴대폰 화면(판매자 앱 "픽케이크 사장님", 기획 I-48)을 만들거나 고칠 때 이 문서를 먼저 본다.
값은 코드가 정본이다. 색·글자·모서리는 `apps/web-seller/src/common/ui/tokens.ts`에 있다. 부품은 `common/ui/`에 있다. 모든 부품은 Storybook "판매자 앱/부품"(`AppUi.stories.tsx`)에서 볼 수 있다.
이 문서는 "어느 부품을 어떤 크기로 쓰는지"와 화면이 지켜야 할 동작·글만 짧게 모은다. 화면을 검토하고 다듬는 작업 방식(전·후 그림으로 골라 받기, 로컬 확인, 올리는 순서)은 skill `picake-seller-app-review`에 있다.

## 먼저 지킬 것

1. **새로 그리지 말고 `common/ui` 부품을 쓴다.** 비슷한 것을 화면 안에서 직접 만들지 않는다. 없으면 `common/ui`에 부품으로 더하고 Storybook에도 넣는다.
2. **크기는 아래 표 값만 쓴다.** `h-[45px]`, `text-[15px]`처럼 표에 없는 값을 쓰지 않는다.
3. **색은 흰색, 회색(`ink-*`), 주황(`brand`) 셋뿐이다.**
   - 연한 주황 바탕과 흐린 주황(투명도)은 쓰지 않는다. 분홍으로 보인다.
   - 갈색·검정·빨강 버튼도 쓰지 않는다.
4. **휴대폰 기본 고르기 창(select·날짜)과 PC 펼침 목록은 쓰지 않는다.** 몇 개 중 하나·날짜·시각 모두 아래에서 올라오는 앱 창으로 고른다.

| ----------- | ------- | -------------------------------------------------------------------- |

| `ink-700`   | #4E4E4B | 칸 이름                                                              |

| `ink-200`   | #D4D4D3 | 입력 칸·보조 버튼 테두리                                             |
| `ink-100`   | #EBEBEA | 나누는 선, 못 누르는 주 버튼 바탕                                    |
| `ink-50`    | #F5F5F5 | 회색 띠·검색 칸·아이콘 칸·빈칸·고른 줄                               |
| `brand`     | #FF653E | 주 버튼, 고른 칩·날짜, 할 일 아이콘, 경고 테두리                     |
| `brand-ink` | #B5401C | 작은 주황 글씨(배지·고칠 곳·경고·오늘 날짜). 버튼 글씨로는 쓰지 않음 |

- **주황은 뜻이 있는 곳에만 쓴다:** 고른 것, 할 일, 주 버튼. 기다리기만 하면 되는 것(주문 "진행 중" 탭 카드 버튼)은 흰 보조 버튼(`CardFooterButton tone="secondary"`)이다.
- **그래프·순위 막대**는 가장 많은 것(1등) 하나만 주황, 나머지는 회색(`ink-200`). 그래프 위에 "토요일이 가장 많아요"처럼 한 줄로도 알린다(주문 통계).
- 고른 상태를 나타내는 방법은 셋 중 하나다.
  - 주황 채움 + 흰 글씨(칩·날짜)
  - 주황 테두리(카드형 선택)
  - 회색 바탕 + 주황 체크(목록 줄)

## 글

- **해요체**로 쓴다. 동의 문구·안내 상자·고칠 곳 문구도 같다("동의해요", "고치는 데 써요").
- **처리한 뒤 안내는 한 일을 말한다**("예약을 확정했어요"). 버튼·창 이름은 상태 이름 대신 하는 일로 쓴다("취소환불대기로 변경"이 아니라 "예약 취소").
- **화면 이름과 같은 말**로 쓴다("영업시간을 저장했어요", "영업 캘린더" 같은 PC 말 쓰지 않기). 켜고 끄는 것은 "노출" 대신 "손님에게 보이기".
- **버튼 이름**: 저장은 "저장하기", 처음 만들 때는 "등록하기", 처리 중에는 "저장하는 중…"·"등록하는 중…".
- **예시 글**은 "예: …"로 쓰고, 케이크 가게가 실제로 쓸 값으로 든다(상호 "달콤케이크", 업태 "제조업", 종목 "제과점업", 이름 "홍길동"). 쓰는 법을 말할 때는 "~를 적어 주세요"(마침표 없이). 손님에게 보이는 글이면 그렇다고 말한다("손님에게 안내할 사유를 적어 주세요").
- **같은 것은 같은 말로**: 주문 카드와 상세처럼 같은 값을 두 곳에서 보이면 이름을 같게 쓴다("입금 마감까지"). PC 말·통계 말("주문건수", "집계", "접수일", "정가") 대신 "주문 수", "픽업 완료한", "주문받은 날", "할인 전 가격".
- **고칠 곳 문구**도 해요체이고 화면에 보이는 칸 이름을 쓴다("판매가는 0원보다 커야 해요", "할인 전 가격"). 서버 글과 맞춰 보는 문구(`AUTH_ERROR_MESSAGES` 등)는 서버와 같이 바꾼다.
- **띄어쓰기**: "~해 주세요", 정렬 이름 "~ 순", 글자 수 "0/1,000자".
- **금액**은 어디서나 천 단위 쉼표("30,000원"). 넣는 칸도 넣는 대로 쉼표가 붙는다(`NumberInput thousands`, "원" 칸은 `AffixNumberInput`이 자동). 거르기 창의 가격 칸도 같은 칸이고, 예시 글도 쉼표("예: 38,000").
- **고르기**: "선택" 대신 "고르기"("은행 고르기", "종류를 골라 주세요").
- **조사**는 이름에 맞춰 고른다(`josa.util`: 을/를 `withEulReul`, 은/는 `eunNeun`, 으로/로 `euRo`). "(으)로"·"은(는)"을 그대로 쓰지 않는다.
- **안내 띠(토스트)** 끝에는 마침표를 찍지 않는다("상품을 저장했어요"). 같은 일은 같은 동사("저장했어요", "링크를 복사했어요").
- **시각**은 24시("20:05"). "오후 08:05" 쓰지 않기(`kst-date.util`).
- **오류 안내**에 서버·브라우저 영어 원문("Internal server error", "Request failed with status code 500")을 보이지 않는다. `getApiMessage`가 500·영어 문구를 "일시적인 오류가 발생했어요…"로 바꾼다. 사진 올리기 실패는 사진 칸 아래 한 줄만("사진을 올리지 못했어요. 다시 시도해 주세요.").
- **개발 말 쓰지 않기**: "폼", "클릭", "시스템", "고객"(→ 손님), "가게"(→ 스토어).

## 동작

- **인터넷이 끊기면** 요청을 멈춰 두지 않고 바로 실패시킨다(`networkMode: "always"`). 그래서 `LoadErrorState`가 "인터넷 연결을 확인해 주세요"를 보이고, 연결되면 다시 불러온다. 이미 불러 둔 데이터가 있으면 오류 화면 대신 그대로 보인다(오류 화면은 `isError && !data`일 때만). 로그인 확인(`useMe`)만은 연결을 기다린다.
- **화면을 못 열면**(끊김, 새 버전 배포 직후 옛 화면 조각) 휴대폰은 앱 빈 화면 모양 오류를 보이고 개발 오류 글은 숨긴다. 배포 직후 옛 조각이면 한 번 새로고침한다(`chunk-reload.util`, 10초 안 반복 안 함).
- **날짜**는 올해가 아니면 해를 붙인다("2025년 12월 24일(수)", `kst-date.util`).
- **키보드가 떠 있으면** 아래 버튼 줄은 숨는다. 번호·인증번호처럼 넣자마자 누르는 짧은 화면은 키보드가 떠 있는 동안만 버튼을 칸 바로 밑에 둔다(`PhoneVerifyFields`).
- **고른 값이 맞지 않으면** 저장 전에 그 칸을 주황 1.5 테두리로 두고 아래 한 줄로 알린다. 저장 버튼은 회색이다. 저장 뒤 서버 글로만 알리지 않는다.
- **처리 중에는 다시 눌리지 않는다**(저장·등록 버튼 회색 + "~하는 중…"). 두 번 눌러 같은 것이 두 개 생기지 않게.
- **긴 이름**은 주문 카드·픽업 줄에서 두 줄까지(`line-clamp-2`), 상품 목록·스토어 카드 이름처럼 한 줄 칸은 `truncate`다(13차에 상품 목록 두 줄은 고르지 않음).
- **숫자 칸 키보드**: 전화번호는 `inputMode="tel"`, 계좌번호·사업자번호·금액은 숫자 키보드(`inputMode="numeric"`).
- **저장·등록·삭제 뒤**에는 들어온 곳으로 돌아간다(`useLeaveAfterSave`: 휴대폰에서 앞 화면이 있으면 뒤로, 없으면 목록으로 바꿔 열기). 뒤로를 눌러 방금 저장한 입력 화면이 다시 열리지 않게. 스토어 정보·영업시간은 스토어 탭으로, 스토어를 처음 만들면 홈으로.
- **지울 때 묻는 창**은 되돌릴 수 없다는 것과 무엇이 사라지는지 한 줄(`useFrameConfirm description`). 주문이 있는 상품은 서버가 지우지 않는다(지우면 주문까지 지워지는 DB 규칙 때문) → 판매중지·숨김 안내.
- **불러오는 동안** 건수·합계를 "0건"으로 보이지 않는다(비워 두거나 회색 뼈대). "불러오는 중…" 글자 대신 회색 뼈대다(홈 "오늘 픽업", 캘린더).
- **실시간 알림(새 예약 등)** 안내 띠는 띠 전체가 버튼이다: 왼쪽 알림 종(주황) · 제목·내용 · 오른쪽 회색 화살표. 누르면 그 주문 상세로 바로 가고 알림은 읽음(`AlertItem.onClick`). 띠 안에 "보기" 같은 버튼을 따로 두지 않는다(15차 운영자: 실제 서비스처럼). 다 됐다는 안내만 주황 체크다.
- **알림이 몰려 와도** 다시 불러오기는 0.8초 모아 한 번만 한다(`SellerNotificationProvider`). 알림마다 주문 목록 여러 개를 다시 부르면 서버 요청 한도(1분 100회)에 걸려 화면이 "불러오지 못했어요"가 된다. 새 화면을 만들 때도 한 번에 부르는 요청 수를 늘리지 않는다.
- **"오늘"**은 `useKstTodayKey`로 정한다(한국 날짜). 화면을 켜 둔 채 자정이 지나거나 앱으로 돌아오면 다시 정하고, 오늘을 보고 있던 칸·달만 새 오늘로 옮긴다(`useFollowToday`). `useState(() => kstDateKey(new Date()))`처럼 한 번만 정하지 않는다.
- **그사이 바뀐 주문**을 처리하면 서버 말 대신 "그사이 주문 상태가 바뀌어 처리하지 못했어요. 바뀐 상태를 다시 보여 드릴게요"를 띄우고 바뀐 상태로 다시 불러온다(`useOrderStatusMutation`).
- **주문 찾기**는 칸 하나로 이름·전화번호 뒷자리(4자리 이상)·상품명·주문번호를 함께 찾는다(서버 `keyword`). 결과 카드에는 예약자 이름을 보인다.
- **사진 여러 장**은 첫 장이 대표다. 둘째 사진부터 누르면 "이 사진을 대표 사진으로 할까요?" 창이 뜨고 "대표로 하기"로 맨 앞으로 온다(`ImageMultiUpload`, 상품·피드). 지우기는 ×.

## 휴대폰 틀(MobileFrame) 안 PC 화면

상품 등록·수정, 피드, 스토어 정보·만들기는 아직 PC 화면 코드를 휴대폰 틀에 담아 쓴다.

- 틀 안에서는 PC 부품(`BaseButton`, `BaseInput`, `Textarea` 등)이 위 기준대로 그려진다. 작은 버튼(`size="sm"`)도 40이고, 안내 글은 13 회색(`text-sub text-ink-600`, PC 14 쓰지 않음).
- `globals.css`의 `.app-form`이 PC 색 이름(primary·accent 등)을 앱 색으로 바꾼다. 틀 안 `accent`는 회색이다.
- 새로 고칠 때는 `useInMobileFrame()`으로 틀 안을 나눈다. 틀 안 쪽은 `common/ui` 부품(`Chip`, `SheetSelect`, `Switch` 등)을 쓴다.
- 아래 저장 줄은 `FrameSubmitBar`다(늘 화면 맨 아래, `BottomActionBar`와 같은 모양). 버튼은 `FRAME_SUBMIT_BUTTON_CLASS`(48)를 쓴다.
- 숫자 칸에 이름·단위가 붙으면 칸 안에 둔다("지름 □ cm", "□ 원", 부품 `AffixNumberInput`). 한 줄에 칸 둘까지, 넘치면 줄을 나눈다(상품 사이즈 줄). 금액 칸은 가장 큰 값("1,000,000 원")이 360 폭에서 들어가는지 본다 — 옵션값은 이름 | × / 추가금(한 줄 가득) / 손님에게 보이기 세 줄.
- 못 누르는 체크는 흐리게(흐린 주황) 하지 않고 회색(`Checkbox`가 틀 안에서 자동). 넣지 않는 항목은 체크를 푼 빈 칸으로 보인다.
- 단계가 있는 화면(스토어 만들기)은 앞 단계로 위쪽 ←로 간다. 아래 버튼 줄은 둘까지("고칠 곳 n개 | 등록하기").
- 고칠 곳이 있으면 "고칠 곳 n개"(보조) | 주 버튼(`flex-[2]`)으로 둔다.
- 고칠 곳·입력 중 모양은 앱 `Field`와 같다. 고칠 곳은 주황 테두리 1.5 + 아래 문구 12/600 #B5401C이고(`.app-form`이 `border-destructive`·`p.text-destructive`를 바꿈), 묶음 제목 색은 검정 그대로다. 입력 중은 진한 검정 테두리 1.5다. 고칠 곳 문구는 칸 이름과 같은 낱말로 쓴다(칸이 "종류"면 "종류를 골라 주세요").
- 틀 안 창(`Dialog`)도 앱 창처럼: 입력 칸은 `Textarea`·`BaseInput`, 칸 이름 13/700, 아래 버튼은 가득 찬 48(`FRAME_SUBMIT_BUTTON_CLASS`, 흰 보조 | 주황 주 버튼), 약한 행동은 회색 글자(`Button variant="quiet"`). 노란 강조 대신 #B5401C 굵은 글씨(예: AI로 쓰기 창).
- 밝은 화면만 쓴다: `color-scheme: only light`(globals.css·index.html). 휴대폰이 어두운 모드여도 웹뷰·브라우저가 강제로 어둡게 바꾸지 않는다.
- 마우스 올림(hover) 꾸밈은 마우스가 있는 기기에서만 나온다(tailwind `hoverOnlyWhenSupported`). 휴대폰에서 누른 버튼이 회색으로 남지 않게.
- 네이버 가져오기 창(상품)의 "옵션 하나씩 정하기"도 앱 모양이다: 줄마다 [체크 | 이름·가격] / [넣을 곳 — `SheetSelect`] / (사이즈면) [사이즈 | 지름 □ cm]. 창 안에서 여는 고르기 창은 그 위에 겹쳐 열린다(11-10 14차).

## 새 화면을 만들 때 확인

- [ ] 버튼·칸 높이가 48/40/36 중 하나인가
- [ ] 아래 버튼은 화면 맨 아래에 붙어 있는가(내용이 짧아도)
- [ ] 분홍(연한 주황 바탕·흐린 주황)이 없는가
- [ ] 휴대폰 기본 고르기 창(select·날짜) 대신 앱 창(`SheetSelect`·`DateRangeSheet`·`TimeSlotSheet`)을 썼는가
- [ ] 빈 화면이 남은 칸 가운데인가(`EmptyState big`)
- [ ] 글이 해요체이고, 처리 안내가 한 일을 말하는가
- [ ] 인터넷이 끊겨도 "없어요"로 보이지 않는가, 불러오는 동안 "0건"이 보이지 않는가
- [ ] 오류가 났을 때 영어 원문이 보이지 않는가, 저장한 뒤 뒤로를 눌러 입력 화면이 다시 열리지 않는가
- [ ] 360 폭(작은 휴대폰)에서 글·칩·숫자 칸이 넘치거나 두 줄로 밀리지 않는가
- [ ] 켜고 끄는 설정은 `Switch` 줄, 삭제는 "저장하기" 아래 회색 글자인가
- [ ] 같은 일을 하는 다른 화면과 모양·이름이 같은가(먼저 비슷한 화면을 찾아 맞춘다)
- [ ] 새 부품을 만들었으면 Storybook에 넣었는가
