# Picake Web Seller

Picake 플랫폼을 위한 React + Vite 기반 판매자 관리 시스템입니다. Shadcn/ui + Tailwind CSS와 최신 웹 기술을 활용하여 직관적이고 효율적인 판매자 경험을 제공합니다.

## 🏗️ 주요 기능

### ✅ 구현 완료

- **인증 시스템**: Google OAuth, Kakao OAuth, Naver OAuth(2026-11-16, 손님과 같은 네이버 앱, `VITE_PUBLIC_NAVER_CLIENT_ID`가 없으면 버튼을 숨김), 계정 찾기
- **PC 화면(기획 I-54, 2026-11-19)**: 휴대폰 화면과 같은 주소·같은 조각으로 PC 틀(`DesktopLayout` + 왼쪽 메뉴 `DesktopNav`, 시안 D: 흰 바탕, 주황은 뜻 있는 곳만)을 그린다. 폭 구간은 `common/constants/screen.constant.ts` 한 곳: ~767 휴대폰, 768~1199 아이콘 메뉴, 840부터 목록 | 상세 두 칸, 1200부터 이름이 보이는 메뉴(앱 안 아이패드도 같은 규칙). PC 화면을 따로 만든 곳은 함께 보여 줄 것이 다른 다섯 곳 — 홈(숫자 칸·주간 보기·처리할 일), 주문(표 | 상세, 줄에서 바로 처리), 상품(표·판매 스위치), 캘린더(달력 칸에 픽업 줄 + 고른 날), 채팅(목록 | 대화). 나머지는 휴대폰 화면을 PC 틀 가운데 칸(720, 상품 등록·수정은 미리보기와 함께 1120)에 그대로 쓰고, 아래 창은 화면 가운데 창으로 열린다(`ShellContext`). 기능은 휴대폰과 같거나 더 많다(운영자 결정): PC에만 주문·매출 엑셀 내려받기(CSV, 손님 휴대폰 번호 빼고), 그날 주문서 묶음 인쇄(`/print/orders?date=`, 새 탭), 상품 등록·수정 중 오른쪽 손님 화면 미리보기, 알림 설정 "이 컴퓨터"(주문 알림 소리·브라우저 알림, 앱 안에서는 숨김). 예전 PC 화면(`AdminLayout`, 검은 주 버튼)은 지웠다. 주소마다 휴대폰·PC 화면이 다 있는지는 `paths.constant.test.ts`가, 화면은 `yarn web-seller:test:e2e`(PC 1440·태블릿 1024/834/768·휴대폰 390)가 본다
- **사업자진위확인**: 국세청 API를 통한 사업자등록번호 진위확인
- **스토어 등록**: 사업자 진위확인 → 스토어 정보 입력 및 생성(통신판매사업자 단계는 꺼 둠, [가이드](../common/feature/스토어%20등록%20-%20가이드.md))
- **스토어 관리**: 스토어 정보 수정, 홈 대시보드, 캘린더
- **스토어 만들기**: 2단계(사업자 진위 확인 → 스토어 정보). 통신판매업 신고 정보 단계는 `REQUIRE_ONLINE_TRADING_REGISTRATION`(false)로 꺼 둠(법 검토: 동네 음식료 판매는 전자상거래법 제3조 ④로 신고 의무 없음). true로 바꾸면 3단계로 돌아옴
- **스토어 등록·수정 폼**: 상품 폼과 같은 모양(섹션: 기본 정보 → 손님 연락 채널 → 위치 → 정산 계좌 → 환불·취소 규정), 아래에 붙은 저장 버튼, 막는 칸이 있으면 "고칠 곳 n개 보기"로 그 섹션으로 이동, 설명 최대 2,000자(`features/store/components/forms/StoreCreationForm.tsx`, 섹션 틀은 `common/components/sections/FormSection.tsx`). 손님 연락 채널(`features/store/components/StoreContactChannels.tsx`)은 Picake 채팅·카카오톡 채널·인스타그램·전화가 한 줄씩(회색 아이콘 · 이름과 적은 값 · "손님에게 보이기" 스위치)이고, 줄을 누르면 아래 창에서 ID·번호를 적는다(운영자 2026-11-20 시안 B). 전화번호는 꼭 적는 칸이라(판매자 정보로도 쓰는 번호) 비우고 저장하면 그 줄에 고칠 곳 문구가 보인다. 스위치(기획 I-01 2026-11-19)를 끄면 값이 있어도 손님 화면 문의 창에서 빠지고, 칸이 비면 켤 수 없다. 운영자 대신 입력 중에는 잠김(상품의 손님에게 보이기와 같게, 서버도 403). 예약한 손님은 주문 화면에서 늘 채팅할 수 있다
- **네이버 플레이스 가져오기**: 스토어 등록·수정 위 한 줄 안내의 버튼으로 창을 열어 네이버 링크로 이름·설명·연락처·인스타그램 ID를 골라 채우고 네이버 매장 연결·해제, 캘린더에서 네이버 영업시간으로 정기 휴무·표준 영업시간 채우기(`features/store/components/naver/`)
- **상품 관리**: 상품 목록, 등록, 상세/수정, 고시는 원산지만 받음(`PRODUCT_NOTICE_MODE`, 법 검토: 동네 음식료 판매는 전자상거래법 제3조 ④로 상품정보제공 고시 미적용, 원산지는 원산지표시법). "ALL"로 바꾸면 14개 항목·고시 복사가 돌아옴
- **네이버 상품 가져오기**: 상품 등록 위 "네이버에서 가져오기" 창에서 연결한 네이버 매장의 예약 상품을 골라 이름·설명·사진·사이즈별 가격·추가 옵션(네이버 맛 분류는 필수 "맛")을 묶음 단위로 골라 채우고(내 상품이 맞아요, 채우기) 등록 때 네이버 상품도 연결, "옵션 하나씩 정하기"를 펼치면 옵션마다 사이즈·판매가·추가 옵션·넣지 않음을 고르고, 포장주문처럼 묶인 상품은 옵션 하나만 상품으로 가져오기, 상품 수정에서 다시 불러와 비교(기본 미선택)·품절·사라진 상품 안내(`features/product/components/naver/`)
- **상품 등록·수정 폼**: 탭 없이 한 화면(사진 → 이름·종류 → 가격·사이즈(손님 결제 금액 표시, 견적 받기 상품은 "손님 화면 ○원~") → 추가 옵션(맛도 여기: 하나 고르기 "맛") → 상세 설명 → 원산지), 같은 사이즈 두 번 금지, 옆 칸에 판매 상태·분류·태그(분류는 2026-11-15부터 상황·디자인(하트·2단 포함)·서비스 세 칸, 칸마다 한 줄 질문, 레터링도 사장님이 고름 — `PRODUCT_CATEGORY_GROUPS`), 아래에 붙은 저장 버튼. 저장을 막는 칸이 있으면 그 섹션으로 이동(`features/product/components/forms/ProductCreationForm.tsx`). 커스텀 케이크는 종류 아래 "주문 받는 방법"(예약 받기 / 견적 받기, 종류와 같은 카드, 처음엔 예약 받기, 기획 I-01 2026-11-19) — 견적 받기면 손님 화면에 예약신청 대신 "이 디자인으로 견적 받기"(이 가게에만), 목록에 "견적 받기" 표시. 기본 케이크로 바꾸면 예약 받기로 돌아간다
- **단위 테스트**: `yarn workspace @picake/web-seller test` (vitest `unit` 프로젝트, `src/**/*.test.ts`). 네이버 가져오기 가격 계산 등 순수 로직
- **브라우저 e2e**: `yarn web-seller:test:e2e` (`apps/web-seller/e2e`, Playwright). 형제 폴더 backend의 테스트 서버·테스트 DB와 심사용 가게(상태별 예시 주문·채팅)로 PC·태블릿·휴대폰 폭의 주요 흐름을 눌러 본다. 심사용 로그인 테스트 코드(000000)는 테스트 DB에서만 맞는다(상용·staging은 서버 비밀값). 서버 요청 한도 때문에 파일마다 탭 하나에서 메뉴를 눌러 옮겨 다닌다. CI `test-web-e2e`는 결과만 보고
- **상세정보 AI 초안**: 상세 설명의 "AI로 쓰기" 창에서 네이버 설명·확인한 사실로 초안을 만들어 바꾸거나 끝에 붙이기. `[판매자 확인 필요]`가 남으면 저장되지 않음
- **주문 관리**: 주문 목록, 주문 상세, 상태 관리
- **피드 관리**: 피드 목록, 작성, 상세
- **통계**: 주문/매출 통계 대시보드
- **직접 적은 주문(기획 I-42)**: 카톡·인스타·전화 등 Picake 밖에서 받은 주문을 휴대폰 화면에서 적으면 Picake 주문과 같은 달력(회색 점, 4건부터 숫자)·그날 목록(시각 순, 오른쪽에 받은 곳)·이번 주 매출·주문 통계(받은 곳 막대)에 섞인다. 홈 고른 날 목록 끝 "주문 적기"·캘린더 아래 "M월 D일 주문 적기"로 들어가 고른 날이 미리 골라진다. 맨 위 "대화 붙여 넣기"(복사해 둔 대화를 바로 읽음, 못 읽으면 붙여 넣는 창)·"캡처로 채우기"로 AI가 칸을 채우고 스낵바 "되돌리기"로 비운다. 날짜 창(`DateSheet`)에는 날마다 받은 수·휴무·대목. 상세에서 입금 전·받음을 바로 바꾼다. 캘린더 오른쪽 위 버튼으로 다른 캘린더로 내보내기(아이폰·구글·주소 복사, 손님 이름 기본 가림, 안드로이드는 아이폰 줄 숨김). 대목·기념일(새해·설날·밸런타인·화이트데이·어린이날·어버이날·스승의날·성년의날·부부의날·추석·할로윈·빼빼로데이·이브·성탄절·연말, 설날·추석은 2030년까지 날짜 표)은 날짜 아래 작은 글씨(`common/utils/cake-days.util.ts`). PC 캘린더에는 보이기만(`features/manual-order/`)
- **알림**: 알림 목록, 알림 설정
- **견적 예약(기획 I-01)**: 손님이 고른 입점 가게 견적으로 예약하면 주문 탭에 예약신청으로 들어온다(이후는 상품 예약과 같음). 주문 상세(휴대폰·PC)에 "견적 예약" 칸(손님 요청서·요청 사항·참고 사진·내 견적 메모), 채팅 요청서 카드에 [예약 보기]. 손님이 예약하기 전까지는 고른 견적도 고칠 수 있다. 참고 사진이 여러 장이면 1·2·3 번호(손님 설명의 "1번 사진처럼"과 맞춤).
- **채팅(기획 I-11)**: 아래 탭 "채팅"(홈·주문·상품·채팅·스토어, 캘린더는 홈 "캘린더 보기"로), 목록 `/stores/:storeId/chats`(답할 것/전체), 방 `/chats/:threadId`(판매자 앱 푸시 `data.path`와 같음), 주문 상세 연락처 옆 "채팅"으로 픽업 전 예약 손님에게 먼저(`/chats/order/:orderId`, 첫 글에 주문 카드). 홈 "처리할 일"의 "견적 요청"·"답할 채팅", 알림 설정의 채팅 알림·밤 끄기. 손님 견적 요청(기획 I-46 ②)은 그 손님 채팅방 맨 위 요청서 카드로 와서 [어려워요]·[견적 보내기](금액·비슷한 정도·사진·메모, 주문 받는 곳은 묻지 않음)로 답하고, 손님이 고르면 그 방에서 주문을 정한다(`features/quote/components/QuoteRequestPanel.tsx`). 요청서 카드의 사진은 번호만(가져올 것은 설명 글에), 설명은 6줄까지 보이고 실제로 잘렸을 때만 "더 보기", 케이크는 1개면 "1호 케이크 · 생크림"처럼 개수 없이(기획 I-112, 11-14). 사진을 누르면 앱 어디서나 `ImageLightbox`(확대·돌리기·넘기기·앱에서 사진 저장). 관리자가 연 뒤에만 보임. 자세한 것은 `docs/common/feature/채팅 시스템 - 가이드.md`
- **마이페이지**: 판매자 정보 조회/수정
- **운영자 대신 입력(기획 I-41)**: 관리자 화면이 연 `/act-as#code=…`(코드는 # 뒤 — 접근 기록에 남지 않게, 예전 `?code=`도 받음)가 한 번만 쓰는 코드를 대리 출입증으로 바꿔 이 탭의 sessionStorage에만 둔다(사장님 출입증 localStorage는 그대로, `common/utils/act-as.util.ts`. 저장소에 못 쓰면 들어가지 않고 세션을 바로 끝냄). 대리 입력 중 로그아웃은 대신 입력 끝내기로 바뀌고(PC 위쪽의 스토어 만들기·마이페이지·로그아웃은 감춤), 마지막 스토어는 들어간 가게로만 읽고 운영자 브라우저에 적지 않는다(`last-store.util.ts`). 끝낸 탭은 표시를 남겨 뒤로 가기로 사장님 화면 주소에 와도 끝난 화면으로. 캘린더 "다른 캘린더로 내보내기" 버튼은 감춘다. 맨 위 고정 검정 띠 "운영자 대신 입력 중 · 스토어 이름 · n분 남음 · 끝내기"(`ActAsBanner`, 띠 높이만큼 `--act-as-band`로 화면·위쪽 줄·알림 배너를 내림). 끝내기·60분·관리자가 끝내면(서버 401) `/act-as/ended` "운영자 대신 입력이 끝났어요". 대리 입력 중에는 PostHog를 켜지 않고(들어오기 주소부터), 실시간 알림 소켓·앱 알림 토큰 등록을 하지 않는다. 채팅·피드·마이페이지·스토어 만들기 화면은 "운영자 대신 입력 중에는 쓸 수 없는 기능이에요"(`ActAsBlockedScreen`), 그 밖의 막힌 일(주문 상태 바꾸기·알림 설정 등)은 서버 글이 위쪽 알림으로. 상품 등록 화면은 "손님에게 보이기"가 꺼진 채 잠기고(서버가 숨김으로 저장), 수정 화면에서도 잠긴다(사장님이 켬, 서버도 바꾸면 403), 스토어 정보의 정산 계좌 칸도 잠긴다. 운영자가 만든 상품(목록 "손님에게 숨김 · 운영자 입력", PC 배지, 수정 화면 알약)과 직접 적은 주문(그날 목록 줄 맨 앞·상세 알약·PC 캘린더 그날 목록)에는 "운영자 입력"이 사장님에게도 보인다
- **상태 관리**: Zustand를 활용한 전역 상태 관리
- **API 통신**: TanStack Query + Axios를 활용한 서버 상태 관리
- **에러 처리**: Error Boundary와 Sentry 연동
- **디자인 시스템**: Shadcn/ui + Tailwind CSS (Material-UI에서 마이그레이션 완료)

## 🔗 주요 페이지

### 인증 관련

- **로그인**: `/auth/login` - Kakao/Naver/Google 소셜 로그인(카카오→네이버→구글 순서). 로그인 전 화면(로그인·계정 찾기·소셜 로그인 뒤 가입)은 PC도 휴대폰 화면을 쓴다(2026-11-20 운영자 결정, 옛 PC 카드 화면은 지움). PC 브라우저 로그인만 좁은 칸을 가운데에 두고(로고·문장 가운데) 아래에 운영사 정보 작은 글(상호·대표·사업자등록번호·통신판매업신고·주소·전화·이메일, 2026-11-17 네이버 로그인 검수 반려로 넣음, `BusinessInfoLines`, 값은 `common/constants/business-info.constant.ts`). 휴대폰·앱 안 로그인 화면에는 두지 않는다. 휴대폰·PC 모두 이 기기에서 마지막으로 로그인(가입 포함)한 방법 버튼에 주황 말풍선 "최근 로그인"(`RecentLoginBubble`, 기기 저장소 `picake:last-login-provider`, 탈퇴하면 지움, 심사용 로그인은 남기지 않음, 2026-11-16)
- **심사용 로그인 창**(휴대폰 로그인 화면의 로고를 2초 안에 10번, SC-62, `ReviewLoginSheet`): 6자리 코드 → `POST /v1/seller/auth/review-login`. 코드는 레포에 두지 않는다(서버 비밀값 `SELLER_REVIEW_LOGIN_CODE_SHA256`에 해시만). 들어가면 손님 목록에 보이지 않는 심사용 가게와 상태별 예시 주문
- **계정 찾기**: `/auth/login/find-account` - 계정 정보 찾기
- **Google 콜백**: `/auth/login/google` - Google OAuth 콜백
- **Kakao 콜백**: `/auth/login/kakao` - Kakao OAuth 콜백
- **Naver 콜백**: `/auth/login/naver` - 네이버 로그인 콜백(state 확인, 가입은 카카오와 같은 화면 — 네이버 번호로 문자 인증 없이, 약관은 늘 받음)
- **이용약관**: `/terms/terms-of-service`
- **운영자 대신 입력(기획 I-41)**: `/act-as#code=…` 들어오기, `/act-as/ended` 끝난 화면(로그인 확인 밖)
- **개인정보처리방침**: `/terms/privacy-policy` (두 화면 모두 관리자가 넣은 약관 HTML을 `dompurify`로 걸러 보여 준다, 손님 웹과 같게)

### 스토어

- **스토어 등록**: `/store/create` - 2단계(사업자 진위 확인 → 스토어 정보) 스토어 개설 흐름
