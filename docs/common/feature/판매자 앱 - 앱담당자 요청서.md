# 판매자 앱 - 앱담당자 요청서

> **2026-11-13부터 앱 껍데기는 `picake-engineering-app`(Capacitor)에서 운영자 쪽이 직접 만듭니다.** 이 문서는 앱담당자에게 부탁하던 때의 기록이고, 지금 약속 정본은 앱 레포 `docs/bridge-contract.md`, 시험은 `docs/testing.md`입니다.

판매자 앱 "픽케이크 사장님"(기획 I-48)의 앱 껍데기(당시 Flutter)가 할 일입니다. 화면·로그인·주문 처리는 모두 판매자 웹(`web-seller`)이 하고, 앱은 웹 화면을 담아 휴대폰 기능만 맡습니다. 손님 앱과 같은 구조이고, 같은 일을 하는 브릿지는 이름도 같습니다.

- 웹은 "앱 안인가"가 아니라 **채널이 있는지**로 기능을 고릅니다. 앱이 어떤 채널을 넣지 않으면 그 기능만 휴대폰 브라우저처럼 동작합니다(공유는 브라우저 공유 창·복사, 사진은 다운로드, 버전은 웹 버전).
- 웹 화면은 배포하면 바로 바뀝니다. 스토어 업데이트는 앱 껍데기를 바꿀 때만 합니다.
- 웹 코드: `apps/web-seller/src/common/utils/webview.bridge.ts`(채널), `common/components/providers/SellerAppBridgeProvider.tsx`(연결). 서버 알림: backend `apps/backend/src/modules/fcm/services/seller-fcm-push.service.ts`.

## 1. 먼저 부탁할 것: Apple 개발자 계정 설정

판매자 Apple 로그인(심사 4.8)을 만들고 시험하려면 이 설정이 먼저 있어야 합니다. 손님 웹이 쓰는 **Services ID에 아래를 더해** 주세요(새 Services ID·새 키는 필요 없음, Team ID·Key는 손님과 같은 것을 씀).

| 칸                     | 넣을 값                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Domains and Subdomains | `api.picakes.com`, `api-staging.picakes.com`                                                                             |
| Return URLs            | `https://api.picakes.com/v1/seller/auth/apple/callback`, `https://api-staging.picakes.com/v1/seller/auth/apple/callback` |

- 판매자 웹은 정적 사이트라, Apple이 POST로 보내는 응답을 서버가 받아 판매자 웹 `/auth/login/apple`로 넘깁니다. 위 주소는 이 방식으로 **만들 예정인 주소**입니다(서버 작업은 운영자 쪽).
- 손님 staging Return URL(`https://staging.picakes.com/auth/login/apple`)을 아직 넣지 않았다면 함께 넣어 주세요.

## 3. 브릿지

웹 → 앱 채널은 JavaScript 채널(`postMessage`), 앱 → 웹은 앱이 `window`의 함수를 부릅니다.

| 방향      | 이름                                                             | 하는 일                                                                                                                                                                                   | 손님 앱과 |
| --------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| 웹 → 앱   | `requestFcmTokenUpsert.postMessage("true")`                      | 로그인 직후(로그인할 때마다 한 번), 처음 사용 안내에서 알림을 허용한 직후. 이 휴대폰의 FCM 토큰을 달라는 요청                                                                             | 같음      |
| 앱 → 웹   | `window.FcmToken.upsert({ token, deviceId })`                    | 토큰을 주면 웹이 서버에 저장. FCM 토큰이 바뀌었을 때(`onTokenRefresh`)도 불러 주세요. 로그인 전이면 웹이 무시합니다                                                                       | 같음      |
| 웹 → 앱   | `requestFcmTokenRemove.postMessage("true")`                      | 로그아웃할 때 토큰 해제 요청. **3초 안에 아래 `remove`로 답해 주세요.** 답이 없으면 웹이 그냥 로그아웃하고, 그 휴대폰으로 알림이 계속 갈 수 있습니다                                      | 같음      |
| 앱 → 웹   | `window.FcmToken.remove({ deviceId })`                           | 웹이 서버에서 이 휴대폰을 빼고 로그아웃                                                                                                                                                   | 같음      |
| 웹 → 앱   | `openAppSettings.postMessage("true")`                            | 휴대폰 설정의 이 앱 알림 설정 열기                                                                                                                                                        | 같음      |
| 웹 → 앱   | `apps://` + 주소로 시작하는 링크                                 | 앞의 `apps://`를 떼고 휴대폰 브라우저나 그 앱으로 열기(설정의 문의하기, 카카오톡 채널·인스타그램·네이버 지도)                                                                             | 같음      |
| 웹 → 앱   | `tel:`·`sms:` 링크                                               | 전화·문자 앱 열기(주문 상세 예약자 연락처)                                                                                                                                                | 같음      |
| 웹 → 앱   | `getPushPermission.postMessage("true")`                          | 지금 알림 허용 상태를 묻습니다(웹이 열릴 때)                                                                                                                                              | **새로**  |
| 웹 → 앱   | `requestPushPermission.postMessage("true")`                      | 휴대폰 알림 허용 창을 띄웁니다(처음 사용 안내 "알림 받기", 홈 "켜기"). 이미 정해진 상태라 창이 안 뜨면 그 상태로 바로 답해 주세요                                                         | **새로**  |
| 앱 → 웹   | `window.receivePushPermission(status)`                           | 위 두 요청의 답. `"granted"` · `"denied"` · `"notDetermined"` 중 하나. **앱이 다시 앞으로 올 때마다(resume) 불러 주면** 휴대폰 설정에서 알림을 바꾸고 돌아왔을 때 홈 안내가 바로 바뀝니다 | **새로**  |
| 웹 → 앱   | `shareLink.postMessage(JSON.stringify({ title, url }))`          | 휴대폰 공유 창(손님에게 스토어·상품 링크 보내기)                                                                                                                                          | **새로**  |
| 웹 → 앱   | `saveImage.postMessage(url)`                                     | 그 주소의 사진을 받아 사진첩에 저장(주문 참고 사진 크게 보기 → "사진 저장"). 웹은 저장 결과를 따로 안내하지 않으니 **앱이 "사진첩에 저장했어요" / 실패 안내를 짧게** 보여 주세요          | **새로**  |
| 앱이 넣음 | `window.PicakeSellerApp = { version: "1.0.0", platform: "ios" }` | 마이페이지 "버전"에 앱 버전이 보입니다(`platform`은 `"ios"` 또는 `"android"`, 로그인 화면에는 버전을 두지 않음). 문서 시작 시점에 넣는 것을 추천합니다                                    | **새로**  |

알림 허용 상태는 이렇게 맞춰 주세요.

| 웹에 줄 값        | iOS                                | Android 13 이상                    | Android 12 이하 |
| ----------------- | ---------------------------------- | ---------------------------------- | --------------- |
| `"granted"`       | authorized, provisional, ephemeral | 알림 권한 허용                     | 앱 알림 켜짐    |
| `"denied"`        | denied                             | 거부함(다시 묻지 못하는 상태 포함) | 앱 알림 꺼짐    |
| `"notDetermined"` | notDetermined                      | 아직 묻지 않음                     | (없음)          |

- **앱을 처음 켤 때 알림 허용 창을 스스로 띄우지 마세요.** 웹의 처음 사용 안내가 왜 필요한지 먼저 보여 주고 `requestPushPermission`을 보냅니다(손님 앱과 다른 점).
- 처음 사용 안내(`/stores/{storeId}/welcome`)는 앱 안에서 허용 상태가 `notDetermined`이고 이 휴대폰에서 아직 안 봤을 때 홈에서 한 번 보입니다. `getPushPermission`에 답하지 않으면 이 안내와 홈 "휴대폰 알림이 꺼져 있어요"가 나오지 않습니다.

## 4. 휴대폰 알림(FCM)

| 항목         | 할 일                                                                                                                                                                                           |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Firebase     | **손님 앱과 같은 Firebase 프로젝트**에 판매자 앱(iOS·Android)을 새로 추가해 설정 파일을 받으세요. 서버는 이 프로젝트로 보내므로 서버 설정은 바꾸지 않습니다. iOS는 APNs 키를 판매자 앱에도 연결 |
| Android 채널 | 서버가 채널 `order_notifications`로 보냅니다. 이 아이디로 채널 하나를 만들어 주세요(이름 "주문 알림" 제안, 중요도 높음, 기본 소리). 채널은 나누지 않습니다(2026-11-06 결정)                     |
| 알림 아이콘  | Android 상태 표시줄용 흰색 한 색 작은 아이콘, 알림 색 주황 `#FF653E`                                                                                                                            |
| 아이콘 숫자  | iOS 알림에 `badge: 1`이 실려 옵니다. 앱을 열거나 앞으로 올 때 아이콘 숫자를 지워 주세요(숫자 세기는 1차에 넣지 않음)                                                                            |

알림 내용은 `notification { title, body }`와 아래 `data`입니다.

| `data.type`              | 언제                                                                         | `data.path`                          | 그 밖의 `data`       |
| ------------------------ | ---------------------------------------------------------------------------- | ------------------------------------ | -------------------- |
| `SELLER_ORDER`           | 새 예약신청, 입금완료, 손님 취소·환불 요청, 입금 기한 만료 취소, 운영자 변경 | `/stores/{storeId}/orders/{orderId}` | `storeId`, `orderId` |
| `SELLER_MORNING_SUMMARY` | 매일 아침(8시) 그날 픽업 요약, 픽업이 없는 날은 안 옴                        | `/stores/{storeId}`                  | `storeId`            |
| `SELLER_TEST`            | 알림 설정·처음 사용 안내의 "테스트 알림 보내기"                              | `/`                                  | —                    |

- **누르면**: 띄우는 주소 뒤에 `data.path`를 붙여 웹뷰로 엽니다(앱이 꺼져 있었을 때 `getInitialMessage`, 뒤에 있었을 때 `onMessageOpenedApp` 모두). 알림 종류가 늘어도 `path`만 달라지니 앱을 고칠 필요가 없습니다. 로그인이 풀려 있으면 웹이 그 주소를 기억했다가 로그인 뒤 그곳으로 보냅니다.
- **앱을 켜 둔 채 왔을 때**: `SELLER_ORDER`는 휴대폰 알림을 띄우지 마세요. 웹이 같은 내용을 화면 안 알림과 소리로 이미 보여 줍니다(겹쳐 울리지 않게, 기획 I-48). `SELLER_TEST`와 `SELLER_MORNING_SUMMARY`는 화면 안 알림이 없으니 켜 둔 채여도 휴대폰 알림으로 보여 주세요. 특히 테스트 알림은 앱 안에서 버튼을 누르고 바로 받는 것이라 꼭 보여야 합니다.
- 한 계정으로 로그인한 휴대폰 모두 받습니다. 로그아웃(위 `remove`)이나 회원 탈퇴를 하면 그 휴대폰에는 가지 않습니다.

## 6. 같이 확인할 것(staging 빌드, 실제 휴대폰)

- [ ] 앱을 열면 휴대폰 로그인 화면이 뜨고, 위·아래 여백이 상태 표시줄·홈 막대와 겹치지 않는다
- [ ] 카카오·구글로 로그인된다(카카오톡 앱 로그인 포함). 앱을 껐다 켜도 로그인이 남는다
- [ ] 처음 들어가면 "새 예약을 놓치지 않게…" 안내 → "알림 받기" → 허용 창 → "알림을 허용했어요" → "테스트 알림 보내기" → 휴대폰 알림이 온다 → "시작하기"로 홈
- [ ] 앱을 뒤로 보낸 채 손님 화면(staging)에서 예약신청 → 휴대폰 알림 → 누르면 그 주문 상세가 열린다. 앱을 완전히 끈 상태에서도 같다
- [ ] 앱을 켜 둔 채 예약신청이 오면 화면 안 알림만 나오고 휴대폰 알림은 겹치지 않는다
- [ ] 휴대폰 설정에서 알림을 끄고 돌아오면 홈에 "휴대폰 알림이 꺼져 있어요" → "켜기" → 휴대폰 설정이 열린다. 다시 켜고 돌아오면 안내가 사라진다
- [ ] 스토어 탭 톱니(설정) → 알림 설정 맨 위 "이 휴대폰 알림"이 허용 상태를 맞게 보여 준다
- [ ] 스토어 → 손님에게 링크 보내기 → 휴대폰 공유 창
- [ ] 주문 상세 참고 사진 → 크게 보기 → "사진 저장" → 사진첩에 저장되고 안내가 나온다
- [ ] 주문 상세 전화·문자 → 전화·문자 앱
- [ ] 스토어 탭 톱니(설정) → 문의하기 → 바깥 브라우저
- [ ] 마이페이지 "버전"에 앱 버전
- [ ] 상품 등록에서 사진첩·카메라로 사진 올리기
- [ ] 입력할 때 키보드가 아래 버튼을 가리지 않는다. 인증번호 칸은 숫자 키패드
- [ ] 로그아웃 → 로그인 화면, 그 휴대폰으로 알림이 더는 오지 않는다
