# 채팅 시스템 - 가이드

손님과 입점 가게(사장님)가 1:1로 이야기하는 채팅입니다(기획 I-11, 1단계). 2026-11 새로 만들었고, 옛 채팅(`chat_rooms`·`messages` 표, `/chat-room` API, 채팅 전용 소켓)은 쓰지 않습니다. 옛 표는 2026-11-12에 지웠습니다(운영자 결정, backend 마이그레이션 `20261112010000_drop_legacy_chat`).

## 한눈에

| 무엇        | 어떻게                                                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 방          | 손님 × 가게(`Shop`) 하나에 방 하나(`chat_threads`, consumerId+shopId 유일)                                                           |
| 글 보내기   | REST `POST`(같은 `clientId`로 다시 보내도 한 번만 저장)                                                                              |
| 새 글 알기  | 알림 소켓(`/notifications`)의 `chat_updated` 신호(글 내용 없음) → 화면이 REST로 가져옴. 소켓이 끊기면 3초, 붙어 있으면 15초마다 확인 |
| 휴대폰 알림 | 손님 앱·판매자 앱 푸시(`data.path`로 방 열기). 20초 안에 그 방을 봤으면 안 보냄                                                      |
| 열고 닫기   | 따로 여는 시각이 없음. 배포하면 바로 열림(운영자 결정 11-12, 약관·처리방침은 11-12 먼저 적용)                                        |
| 거르기      | 욕설은 저장할 때 `maskedText`(●●)로, 원문은 신고 처리 때 운영자만 봄                                                                 |
| 신고        | 손님·사장님 모두. 디스코드 【PICAKE】운영으로 알림(내용 없이 링크만) → 관리자 `채팅 > 신고 처리`에서 24시간 안 처리                  |
| 지우기      | 손님 탈퇴 시 그 손님의 방·글·사진 지움. 보관: 마지막 글 3년, 신고된 대화는 처리 뒤 1년(운영자 결정 11-11)                            |

## 누가 먼저 말할 수 있나

- **손님**: 언제든(가게 상세 문의 창 "채팅으로 문의", 예약 상세 문의).
- **사장님**: 손님이 먼저 말한 방에서 손님 마지막 글 30일 안, 또는 그 손님의 픽업 전 예약이 있을 때.
  - 주문 상세 연락처 옆 "채팅"(휴대폰 화면 말풍선 버튼, PC "채팅하기")은 픽업 전 예약(예약신청·입금대기·입금완료·예약확정·픽업대기)에서만 보이고, 첫 글에 주문 카드가 붙습니다(운영자 결정 11-11).
  - 그 밖에는 입력칸 대신 "손님 글이 30일 넘게 없고 픽업 전 예약도 없어 먼저 보낼 수 없어요. 손님이 먼저 말하면 다시 보낼 수 있어요."(왜 못 보내는지 한 줄, 운영자 11-12)
- 차단하면 둘 다 못 보냅니다. 사장님이 차단하면 아래 띠에 "되돌리기"가 5초 나옵니다(판매 상태 바꾸기와 같음). 차단한 쪽에는 "차단한 대화예요. 위쪽 ⋯에서 차단을 풀 수 있어요.", 차단당한 쪽에는 "지금은 메시지를 보낼 수 없어요."만 보입니다.

## 서버(backend `modules/chat`)

| 파일                               | 하는 일                                                                                                  |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `constants/chat.constants.ts`      | 숫자 한도(`CHAT_LIMITS`), 규칙 버전, 오류 글, 거를 낱말, 판매자 푸시 제목 "새 문의가 왔어요"             |
| `utils/chat-policy.util.ts`        | 보낼 수 있는지(`decideShopWrite`·`decideConsumerWrite`), 거르기, 미리보기, 밤(21~8시) 판단, 안 읽음 판단 |
| `services/chat.service.ts`         | 손님·사장님 목록·방·글·카드(주문·상품)·차단·알림 끔·신고                                                 |
| `services/chat-notify.service.ts`  | 새 글 뒤 소켓 신호·푸시, 읽음이 바뀌면 상대에게 신호만(`afterRead`)                                      |
| `services/chat-admin.service.ts`   | 신고 목록·상세(열람 기록 `chat_access_logs`)·처리(고른 메시지 가리기)                                    |
| `services/chat-cleanup.service.ts` | 손님 탈퇴 때 지우기                                                                                      |

API는 `docs/backend/README.md`(backend 레포)의 "채팅" 줄을 봅니다. 요약:

- 손님 `/v1/consumer/chats/*`
- 사장님 `/v1/seller/stores/:storeId/chats/*`(목록 `?filter=reply|all`, `orders/:orderId`로 주문에서 먼저 보내기)
- 관리자 `/v1/admin/chat/reports/*`, `/v1/admin/chat/summary`(매일 브리핑 숫자)

### 소켓 신호 `chat_updated`

```ts
{ threadId: string; storeId: string | null; senderName?: string; muted?: boolean }
```

- `senderName`: 손님이 보낸 글일 때만(사장님 화면 안내 "새 문의가 왔어요 · 닉네임"에 씀)
- `muted`: 받는 사람이 그 방 알림을 껐으면 true(화면 안 안내를 띄우지 않음)
- 읽음이 바뀌어도 상대에게 신호를 보냅니다(내용·안내 없음). 상대가 다시 가져와도 새로 읽을 글이 없어 되돌아오지 않습니다.

## 손님 웹(web-user)

- 주소: `/chat`(목록), `/chat/:threadId`(방), `/chat/store/:storeId`(가게에 처음 보내기). 휴대폰 알림 `data.path`도 이 주소
- 코드: `features/chat/*`(API·훅 `useChatRoom`·화면 `ChatRoomScreen`·`ChatListScreen`·규칙/메뉴/신고 창)
- 입구: 가게 상세 "스토어 문의"(늘 보임) 창 맨 위 "채팅으로 문의"(Picake 로고, 운영자 11-12), MY 바로가기 "채팅"(안 읽은 수), 아래 MY 점
- 목록: 가게 로고(없으면 가게 화면과 같은 가게 그림), 시각은 일주일 안은 "N분 전·N일 전", 그 뒤는 "10월 3일"(올해가 아니면 해). 빈 목록·못 불러옴은 다른 MY 목록과 같은 부품(`EmptyState`·`LoadErrorState`, 세로 가운데)
- 로그인하지 않았으면 로그인 안내를 세로 가운데에(내 견적과 같음)
- 입력칸은 글에 맞게 약 4줄까지 늘어납니다(두 앱 같음)
- 내 말풍선은 주황, 사장님 말풍선은 회색

## 사장님 웹(web-seller)

- 아래 탭: 홈 · 주문 · 상품 · **채팅** · 스토어(캘린더는 홈 "이번 주 · 캘린더 보기"로)
- 주소: `/stores/:storeId/chats`(목록, 답할 것/전체), `/stores/:storeId/chats/:threadId`(방, 서버 `buildSellerChatPath`와 같아야 함), `/stores/:storeId/chats/order/:orderId`(주문에서 먼저)
- 코드: `features/chat/*`(API·훅 `useSellerChatRoom`·`SellerChatRoom`), 화면 `pages/store/detail/chats/Chats.mobile.tsx`(PC는 같은 화면을 가운데, 아래 탭 없이)
- 목록: 손님 사진은 주지 않아 사람 그림, 차단한 손님은 "차단함", 시각 규칙은 손님 웹과 같음. 빈 화면·못 불러옴은 주문 탭처럼 세로 가운데
- PC 왼쪽 메뉴 "채팅"은 "주문" 바로 아래(운영자 11-12)
- 홈 "처리할 일"에 "답할 채팅 N"
- 알림 설정: 채팅 알림 받기, 밤 9시~아침 8시 끄기
- 내 말풍선은 주황(손님 앱과 같게, 운영자 결정 11-12 — 판매자 앱 디자인 기준의 채팅 예외), "읽음"은 작은 주황 글씨, 시각은 24시

## 관리자 웹(web-admin)

- `채팅 > 신고 처리`(`/chat-reports`, 상세 `/chat-reports/:id` — 디스코드 알림 링크와 같음): 최근 대화 50개 원문, 가릴 메시지를 골라 "가리고 처리" 또는 "그대로 두고 처리"

## 화면 녹화(PostHog)

말풍선·사진·입력칸·목록 미리보기에는 `ph-no-capture`를 붙여 녹화에서 가립니다(두 앱 `CHAT_NO_REPLAY`).

## 아직 안 한 것

- 알림톡(손님이 앱이 없을 때): 템플릿 문구 확정·검수 전이라 `CHAT_ALIMTALK_TEMPLATE_IDS`가 비어 있음
- 자주 쓰는 답(실제 가게가 생긴 뒤), 운영자가 대신 전하기("Picake가 전해요"), 입점 전 가게와 채팅: 운영자 결정 대기
