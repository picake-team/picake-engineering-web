# 프로젝트 구조 - 가이드

이 문서는 Picake 웹 레포(`picake-engineering-web`)의 구조를 설명합니다. Picake 개발 코드는 아래 레포로 나뉘어 있습니다.

| 레포                         | 내용                                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------------------- |
| `picake-engineering-web`     | 웹 프론트엔드 (`web-user`, `web-seller`, `web-admin`, `web-info`)                             |
| `picake-engineering-backend` | 백엔드 API 서버 (NestJS, `apps/backend`) — 별도 레포                                          |
| `picake-engineering-app`     | Flutter 웹뷰 앱 (손님 앱이 `web-user`를 감쌈, 판매자 앱 준비 중). 코드는 지금 앱담당자가 보관 |

> 백엔드 구조(모듈, 디렉토리)는 backend 레포의 문서를 참고하세요. 아래 트리는 웹 레포만 다룹니다.

## 🧭 앱 구조 원칙 (2026-11-05 정함)

화면이 늘어나도 관리할 앱·도메인·로그인이 늘지 않게 세 층으로 나눕니다.

| 층        | 무엇                                                         | 나누는 기준                                                                                                                                             |
| --------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 웹 앱     | `web-user`, `web-seller`, `web-admin`, `web-info`            | 누가 쓰나 (손님·사장님·운영자·처음 온 사람). 사용자 종류마다 웹 앱 하나, 도메인 하나                                                                    |
| 화면 모양 | 휴대폰 / PC                                                  | 같은 웹 앱 안에서 화면 폭으로 고릅니다. 데이터 부분(API·hooks·타입·상태 규칙)은 같이 쓰고, 화면 파일만 나눕니다(`List.mobile.tsx` / `List.desktop.tsx`) |
| 껍데기    | 브라우저, Flutter 앱(`picake-engineering-app`), 나중에 PC 앱 | 같은 주소를 띄우고 푸시·카메라 같은 기기 기능만 더합니다. 웹은 "앱 안인가"가 아니라 "푸시를 쓸 수 있나"처럼 기능으로 확인합니다                         |

- 같은 일은 같은 주소입니다. 알림·푸시·알림톡 링크 하나가 브라우저·앱 어디서나 같은 화면을 엽니다.
- 프레임워크: 누구나 들어오는 공개 사이트(`web-user`, `web-info`)는 Next.js, 로그인해서 쓰는 도구(`web-seller`, `web-admin`)는 Vite입니다. 판매자 웹을 Next.js로 바꾸지 않기로 했습니다(2026-11-05, 검색 노출이 필요 없고 상품 설명 편집기 `react-quill`이 React 19에서 동작하지 않음).
- 폴더 이름과 도메인은 바꾸지 않습니다. 손님 PC 화면이 필요해지면 `web-user` 안에 PC 화면을 더합니다.
- 앱 쪽 약속(브릿지 이름, 푸시 내용)은 [사용자 - 웹뷰 인증 가이드](../feature/사용자%20-%20웹뷰%20인증.md)에 있습니다. 판매자 앱은 손님 앱과 같은 이름을 씁니다.

### 판매자 웹의 휴대폰 화면 (2026-11-06, 판매자 앱 I-48)

판매자 앱("픽케이크 사장님")은 `web-seller`의 휴대폰 화면을 Flutter 앱이 담습니다. PC용 앱을 따로 만들지 않고 아래처럼 나눕니다.

| 무엇        | 어디                                                                                          | 규칙                                                                                                                                                                                                                               |
| ----------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 화면 고르기 | `common/constants/screen.constant.ts` (`SCREEN_MODE`), `common/hooks/useShowMobileScreens.ts` | 개발·staging은 폭 767px 이하에서 휴대폰 화면, production은 출시를 정할 때까지 지금 PC 화면만. 출시 때 `mobile-everywhere`로 PC에서도 휴대폰 화면을 가운데 640 칸에                                                                 |
| 주소        | `common/constants/paths.constant.ts` (`AppRouteConfig`)                                       | 한 주소에 `element`(PC)와 `mobile`(휴대폰). 휴대폰 화면이 아직 없는 주소는 휴대폰 폭에서도 PC 화면                                                                                                                                 |
| 화면 파일   | `pages/**/Home.desktop.tsx` / `Home.mobile.tsx`                                               | 화면 파일만 나누고 API·hooks·타입·상태 규칙은 `features/`에서 같이 씁니다                                                                                                                                                          |
| 바깥 틀     | `common/components/layouts/MobileLayout.tsx` (휴대폰), `AdminLayout.tsx` (PC)                 | 휴대폰 화면의 위쪽 줄·아래 탭은 화면마다 `AppScreen`으로 그립니다. 아래 탭은 탭 첫 화면 5개(홈·주문·캘린더·상품·스토어)에만                                                                                                        |
| 부품        | `common/ui/`                                                                                  | 디자인 기준 B(글자·색·간격·부품·아이콘·배지) 그대로. 색·글자 크기는 `tokens.ts` → `tailwind.config.ts`(`ink-*`, `brand-*`, `text-title` …, PC 화면의 shadcn 이름과 겹치지 않게). 손님 웹과 공통 패키지로 꺼내는 것은 나중에 합니다 |
| 안내 띠     | `common/ui/ToastHost.tsx`                                                                     | PC와 같은 알림 저장소(`useAlertStore`)를 휴대폰 화면 모양(아래쪽 흰 안내 띠)으로 그립니다                                                                                                                                          |

- 휴대폰 화면의 아래 여백은 디자인의 28 대신 휴대폰이 알려 주는 안전 영역(`env(safe-area-inset-bottom)`)을 씁니다(`index.html`의 `viewport-fit=cover`). 입력 중(키보드가 올라옴)에는 아래 탭과 아래 붙은 버튼을 숨깁니다(`useKeyboardOpen`, 손님 웹과 같은 코드).
- 부품 모음은 Storybook "판매자 앱/부품"(`yarn web-seller:storybook`)에서 봅니다.
