# Picake Web Info

Picake의 정보·소개 사이트(`https://info.picakes.com`)입니다. 서비스 본체(`web-user`)와 분리된 정적 마케팅 페이지를 관리합니다. Next.js(App Router) 기반이고 Vercel에 배포합니다.

## 🔗 주요 페이지

| 경로            | 내용                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/`             | 손님 소개 페이지(2026-11-20 새로, `src/app/page.tsx`): 어두운 하트 케이크 사진 첫 화면(흰 글자, 앱 받기 — 휴대폰 "앱 받기" 하나, PC는 App Store·Google Play·QR 버튼, QR은 눌러서 버튼 줄 오른쪽에 열기, PC 위쪽 줄 "앱 받기"도 첫 화면으로 올려 QR을 연다 — 손님 웹 `/app`은 PC를 손님 웹 홈으로 보내서) → 주문이 오래 걸리는 이유 4칸 → 해결 줄(디자인 고르기·견적 받기·예약, 상용 손님 웹 화면) → 물어보기 전에 여기서(문답 6개) → 예약도 간단해요·이것도 돼요 → 자주 묻는 질문 → "사장님이세요?" 띠 → 운영사(통신판매중개자 고지). 예전에는 사장님 소개를 그대로 보여 주는 rewrite였다(2026-11-14 네이버 서치어드바이저 소유 확인이 첫 주소 404로 실패해서, #404). 네이버 확인 태그는 layout metadata라 첫 주소에도 그대로 있다. 앱 받기 주소는 `common/constants/app-download.constants.ts`(web-user에서 복사) |

## 🧭 설계 원칙

- **휴대폰·PC 둘 다, 글은 한 벌입니다(2026-11-20).** 같은 주소·같은 글을 화면 폭에 따라 배치만 바꿉니다. 폭 구간은 `src/common/constants/screen.constants.ts` 한 곳(휴대폰 ~767, PC `md` 768~, 넓은 PC `lg` 1024~)이고 `tailwind.config.ts`의 `screens`가 이 값을 씁니다. Next.js는 서버에서 먼저 그리므로 JS 폭 훅을 쓰지 않고 CSS(tailwind 반응형)로만 나눕니다(깜빡임 없음). 휴대폰용·PC용 화면을 따로 만들지 않아 검색·AI가 같은 글을 한 번 읽습니다(h1 하나). 사장님 웹의 "휴대폰·PC 나누는 원칙"([프로젝트 구조 - 가이드](../common/structure/프로젝트%20구조%20-%20가이드.md))과 같은 경계예요.
- **문서 전체가 스크롤됩니다.** 예전의 640px 스크롤 칸(`#root-scroll-container`)을 없앴습니다. 위쪽 줄은 `sticky`, 휴대폰 아래 주 버튼(`StickyCta`)은 `fixed`이고, 칸 이동이 위쪽 줄에 가리지 않게 `globals.css`의 `scroll-padding-top`이 위쪽 줄 높이(휴대폰 56·PC 72)보다 8px 큽니다. 스크롤 막대는 휴대폰에서만 숨깁니다.
- **소개 페이지 부품은 `src/common/components/landing`에 모읍니다.** 위쪽 줄(`SiteHeader`: 휴대폰 로고·작은 링크, PC 주 버튼, 넓은 PC 칸 이동 메뉴와 지금 칸 주황 밑줄), 첫 화면(`PhotoHero`: 어두운 사진 + 흰 글자, 휴대폰은 사진 위쪽·글 아래, PC는 글 왼쪽), 칸 부품(`Blocks`: 제목·고민 칸·해결 줄·"이것도 돼요"·왼쪽 제목 칸·자주 묻는 질문·마지막 칸), 화면 틀(`Shots`: 휴대폰·PC), 버튼(`Buttons`), 맨 아래(`SiteFooter`), 휴대폰 아래 주 버튼(`StickyCta`). 모양 값은 `landing.styles.ts`. 한 페이지에만 있는 칸은 `features/<쪽>/components`(사장님 `SellerSections`: 비교표·AI 칸·글|PC 화면·PC 화면 넘기기·처음 시작·0원).
- **web-user와 같은 구성을 따릅니다.** PostHog, 환경 판별(`NEXT_PUBLIC_NODE_ENV`), `robots`/`sitemap` 규칙이 web-user와 같습니다. 정적 소개 페이지라 Sentry는 쓰지 않습니다.
- **필요한 공용 코드만 복사해 씁니다.** 폰트 등은 web-user에서 복사한 것이며 web-user를 수정하지 않습니다. 원본이 바뀌어도 자동으로 따라가지 않습니다.
- **소개 페이지 그림은 실제 화면과 사진만 씁니다.** 판매자 휴대폰 화면 그림은 로컬 예시 가게(테스트 DB "달콤스토어")로, PC 화면 그림(`pc-*.png`, 1440 폭)은 로컬 서버의 심사용 예시 가게를 "달콤스토어"로 보이게 해 찍은 것이고(개발 도구 단추·네이버 안내 줄은 숨김, 2026-11-20), 케이크 사진은 Unsplash·Pexels 무료 사진입니다(`features/seller/assets`, 출처는 페이지 파일 주석). 그림·아이콘·빛번짐으로 꾸미지 않습니다(운영자가 "AI가 만든 느낌"이라고 함). 화면이 바뀌면 picake-hq skill `picake-marketing-image`의 스토어 스크린샷 방법으로 다시 찍습니다.
- **디자인 값은 web-user와 같이 씁니다.** 색·글자 크기·모서리·움직임은 공통 패키지 `@picake/design-tokens`의 손님 화면 preset입니다(`tailwind.config.ts`의 `presets`, 2026-11-08 복사본에서 바꿈). 패키지 값이 바뀌면 web-info도 따라 바뀝니다.
- **콘텐츠는 코드에 직접 작성합니다.** 문구를 고치려면 PR이 필요합니다.

## ✅ 소개 페이지를 만들 때 보는 것

소개 페이지는 DM·검색·AI 답변으로 처음 만나는 곳이라 보기 좋은 것만으로는 부족합니다. 만들기 전에 아래 기준을 세우고, 올리기 전에 하나씩 확인합니다(2026-11-14 운영자 요청).

| 기준        | 확인할 것                                                                                                                                                                                                                                                                                                   |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 설득        | 읽는 사람이 실제로 한 말(설문·방문·DM) 순서로 내세운다. 문장마다 지금 코드와 대조한 사실만 쓰고, 없는 숫자·후기는 쓰지 않는다. 주요 행동(버튼)은 하나                                                                                                                                                       |
| 검색(SEO)   | 사람이 검색할 말(예: 주문제작 케이크·예약·견적)과 한글·영문 이름(픽케이크·Picake)이 `title`·`description`·`h1`에 있다. canonical, `sitemap.ts`의 `lastModified`(내용을 크게 바꾸면 날짜도), 상용만 열린 `robots`                                                                                            |
| AI 검색     | 설명 첫 문장이 "픽케이크는 …예요" 한 문장 정의. 구조화 데이터(`JsonLd`, Organization·WebPage·Service), `public/llms.txt`를 페이지 내용과 같게. AI·검색 로봇이 본문을 읽는지 `curl -A "GPTBot"`·`"Yeti"`로 확인                                                                                              |
| DM 미리보기 | `openGraph` 제목·설명·그림을 그 페이지를 받을 사람에 맞게. 카카오톡·인스타그램은 PNG만 보여 준다                                                                                                                                                                                                            |
| 속도        | 첫 화면 사진(LCP)은 `priority`와 `fetchPriority="high"`. Lighthouse 모바일·PC를 각각 3번 돌려 중간값으로 LCP 2.5초 안을 본다(첫 회는 튈 수 있음)                                                                                                                                                            |
| 접근성      | 확대를 막지 않는다(레이아웃 viewport). 글자 대비 4.5:1, 그림 `alt`(꾸밈 사진은 빈 값). 예외: 입점 버튼(주황 바탕 흰 글자)·첫 화면 머리말·0원·칸 머리말과 제목 속 강조 낱말(메인 주황)은 대비가 낮다는 것을 알고 운영자가 고른 색(2026-11-17·20). 비교표는 휴대폰에서 칸을 쌓아도 표로 읽히게 `role="table"` |
| 신뢰        | 운영사·연락할 곳이 보인다                                                                                                                                                                                                                                                                                   |
| 폭          | 320·390·768·1024·1280·1440 폭에서 옆으로 넘치지 않고 겹치지 않는지 위에서 아래까지 찍어 본다. 휴대폰은 아래 주 버튼이 첫 화면·마지막 칸·맨 아래에서 숨는지, 넓은 PC는 칸 이동 메뉴의 지금 칸 표시가 따라오는지                                                                                              |

## 📊 분석·모니터링

- PostHog는 web-user·web-seller와 **같은 프로젝트**를 쓰고, 이벤트에 `app: "web-info"`·`environment` 속성을 붙입니다. 기존 리포트·루틴은 `app` 필터를 걸고 있어 web-info 이벤트가 섞이지 않습니다.
- `info.picakes.com`과 `picakes.com`은 같은 상위 도메인이라 PostHog 방문자 식별자가 공유됩니다(`cross_subdomain_cookie` 기본값).
- 배포 결과는 다른 웹 앱과 같은 Discord 웹훅으로 가며, 알림 제목에 `web-info`가 표시됩니다.

## 🚀 개발·배포

```bash
yarn web-info:dev      # 개발 서버 (포트: 3004)
yarn web-info:build    # 빌드
yarn workspace @picake/web-info test   # CI 검사와 동일 (next build, 타입 검사 포함)
```

- 배포: `web-info/staging-*`, `web-info/production-*` 태그 푸시 → GitHub Actions → Vercel
- 도메인: 검증 `info-staging.picakes.com`, 상용 `info.picakes.com`
- 환경변수: `NEXT_PUBLIC_NODE_ENV`, `NEXT_PUBLIC_POSTHOG_KEY`, `NEXT_PUBLIC_POSTHOG_HOST`

자세한 배포 설정은 [Vercel 배포 가이드](../infra/vercel/Vercel%20배포%20-%20가이드.md)를 참고하세요.

## ⚠️ 알아둘 점

- 오프라인 QR은 `https://picakes.com/partner`(web-user)를 가리킵니다. 이 주소와 `/partner/about` 리다이렉트는 web-user에서 관리하므로 함부로 없애지 마세요.
- 소개 페이지의 버튼 목적지(입점 신청 = 판매자 웹, 문의 = 카카오톡 채널 "픽케이크" 채팅)는 `common/constants/partner.constants.ts`에서 관리합니다. 2026-11-14부터 소개 페이지에는 설문 버튼이 없습니다(설문은 입점 안내 QR 페이지 `picakes.com/partner`에만).
- 검색 등록: 구글 서치콘솔은 `picakes.com` 도메인 전체(DNS TXT)로 확인돼 있어 info도 포함되고, `sitemap.xml`은 2026-10-28 제출했습니다. 네이버 서치어드바이저는 `info.picakes.com`을 따로 등록하며, 소유 확인 태그가 `src/app/layout.tsx`의 `metadata.verification`에 있습니다(지우면 등록이 풀림). 네이버는 첫 주소(`/`)를 읽으므로 `/`가 200이어야 합니다.
